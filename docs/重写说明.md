# ClashX.Meta 现代化重写说明

## 上游现状（meta 分支，2026-10-22）

约 2 万行 Swift。近期已经部分现代化（actor、async/await、swift-subprocess、SwiftUI 仪表盘、xcstrings），
但骨架仍是 2018 年的：

| 遗留点 | 位置 | 问题 |
|---|---|---|
| RxSwift relay 驱动全部状态 | `AppDelegate`、`ConfigManager`、`ProxyManager` | 与 Swift 并发混用，难以静态检查 |
| Storyboard + XIB + 手写 `NSMenuItem.view` | `Main.storyboard`、`Views/` | 菜单逻辑散在 Factory 与 Delegate 中 |
| `SMJobBless` + `useLegacyInstall = true` | `PrivilegedHelperManager` | API 已废弃，安装流程靠弹窗轮询 |
| Objective-C `ProxySettingTool` + 本地 `AuthorizationRef` | `ProxyConfigHelper/` | Helper 本身就是 root，授权代码多余 |
| 每次启动写一份 launchd plist 再 `launchctl load` | `MetaTask` | 内核脱离 Helper 生命周期，崩溃后残留 root 进程 |
| 通过 `sed` 把内核 MD5 写进源码 | `install_dependency.sh` | 构建脚本修改源码 |
| 30+ SPM 依赖（NIO、async-http-client、SwiftyJSON…） | `Package.resolved` | 只为了几个 HTTP 请求 |

## 重写采用的方式

- macOS 15+，Swift 6 语言模式，`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`，仅 I/O 与内核进程显式 `nonisolated` / actor。
- UI 全部 SwiftUI：`MenuBarExtra(.menu)`、`Settings`、`Window` 三个 Scene；`@Observable AppModel` 做唯一数据源。
- 特权部分用 `SMAppService.daemon` 注册 launchd 守护进程；XPC 只有一个 `send(Data)` 入口，消息为带版本号的 Codable 信封；
  守护进程用 `SecCodeCheckValidity` 校验客户端（要求字符串由构建设置注入，为空时退化为 bundle id 校验并如实上报）。
- 守护进程直接托管 mihomo 子进程；App 全部断开 15 秒后自动停止内核；重启时按 pid 文件清理残留。
- 没有 Helper 时自动降级为用户态启动（只有代理端口，无 TUN / 系统代理），开发与首次体验不需要 root。
- 内核二进制随包附带 `.gz`，首次运行用 libcompression 解压到 Application Support 并校验 SHA-256（清单由脚本生成，不改源码）。
- `geosite.dat` / `geoip.dat` / `country.mmdb` 同样随包附带，仅在配置目录缺失时解压播种，绝不覆盖用户已有文件。
- Profile 推送失败（YAML 错误、缺 geo 数据等）不会杀掉内核：控制器保持可用，错误显示在菜单首行，可直接切换 profile。
- 配置分两层：启动用的 bootstrap（控制器地址、随机 secret、端口避让）+ 用户 profile 经覆盖层（mode/log-level/allow-lan/tun/sniffer/端口）合成后 `PUT /configs`。
  Profile 里的 `external-controller`/`secret`/`external-ui` 会被剥离，端口以启动时分配的为准。
- 网络只用 `URLSession`；`/traffic` `/logs` `/memory` `/connections` 用 `bytes(for:).lines` 读取。
- `xcodegen` 生成工程；纯逻辑放在 SwiftPM 包里，Swift Testing 覆盖配置合成、端口分配、gzip、模型解码（26 个用例）。

## 已验证（本机，用户态路径）

1. `swift test` 26/26 通过；`xcodebuild` ad-hoc 签名构建成功，包内含 Helper 可执行文件与 LaunchDaemons plist。
2. 以独立配置目录（`CLASHX_CONFIG_DIR`）启动：7890 被本机其它代理占用时自动改用 7891；`/version` 正常、无 secret 返回 401。
3. 通过 7891 的 HTTP 与 SOCKS5 代理访问 `cp.cloudflare.com/generate_204` 返回 204；流量流、连接流正常。
4. 修改 profile 文件后自动重载；退出 App 后无残留 mihomo 进程；菜单栏图标与双行速度正常显示（截图确认）。
5. 首次运行把 geosite.dat / geoip.dat / country.mmdb 播种到空配置目录，`GEOSITE,cn` / `GEOIP,CN` 规则正常加载；
   写入非法 YAML 后控制器仍在线，改回后自动恢复。

## 手动验证前须知

- 你当前的 clash 占着 7890，本 App 会自动改用 7891 并在菜单显示 `⚠︎ System proxy was changed by another app`，这是正确行为。
- `~/.config/clash.meta/cache.db` 是 root 所有（旧 ClashX Meta 留下的），用户态内核会在 `core.log` 里报一条打不开缓存的警告，功能不受影响；`sudo chown $USER ~/.config/clash.meta/cache.db` 或删掉它即可消除。
- 用户态模式下 TUN 会被强制关闭，菜单里的 TUN 开关会提示需要 Helper。
- “Install Helper”是唯一没在本机跑过的路径；ad-hoc 签名下注册可能失败，错误会显示在菜单首行。

## 手动验证步骤

```bash
cd ~/Projects/aaadiantongren/clashx-remake
xcodegen generate
xcodebuild -project ClashXRemake.xcodeproj -scheme ClashXRemake -configuration Debug \
  -derivedDataPath build/DerivedData CODE_SIGN_STYLE=Manual CODE_SIGN_IDENTITY=- build
open "build/DerivedData/Build/Products/Debug/ClashX Remake.app"
```

1. 菜单栏出现图标与速度；点开菜单应看到 `mihomo v1.19.33 · User space`、代理模式、`config` 配置等。
   默认使用 `~/.config/clash.meta`，会在菜单“Config”里列出你现有的 yaml，切换即生效。
2. 打开 Dashboard（⌘D）查看总览/代理/连接/日志；Web Dashboard 标签加载托管版 zashboard。
3. 要测 TUN / 系统代理：设置 → Core & Helper → Install Helper，在“登录项与扩展”里允许后重启内核，
   菜单状态应变为 `Privileged (helper)`。退出 App 会还原系统代理与 DNS。
